# Deployment guide (iPhone-friendly)

Everything below can be done in **Safari on iPhone**. Use "Request Desktop Website" (aA menu in the
address bar) on Heroku and MongoDB pages if a button is hidden.

---

## 1. Telegram setup (Telegram app + Safari)

1. **Bot token** — open @BotFather → `/newbot` (or `/mybots` → your bot → API Token). Copy the token.
2. **API ID / hash** — Safari → <https://my.telegram.org> → log in with your phone → *API development tools* → create an app → copy `api_id` and `api_hash`.
3. **Create two channels** (Telegram → ✏️ → New Channel):
   - `ANIME SOUL Storage` — **private**. Files are stored here.
   - Your public **ANIME SOUL** channel — announcements go here (you may already have it).
4. Add the bot as **administrator** in both channels with *Post messages* (and *Edit/Delete messages*) permissions.
5. For every **FSUB** channel, add the bot as administrator too (needed to check membership and create invite links). For join-request mode it also needs *Invite users via link*.
   **Permissions the bot needs**

   | Channel | Bot role | Permissions |
   |---|---|---|
   | Storage (private) | Admin | Post messages (uploads), Edit messages |
   | ANIME SOUL post channel | Admin | Post messages, Edit messages (to fix a post) |
   | Test channel (optional, private) | Admin | Post messages |
   | Each FSUB channel | Admin | None required to read members; **Invite users via link** for invite buttons and join-request mode |

6. IDs: after deploying (step 4), open the bot and send `/id` → that's your `OWNER_ID`. Forward any post from each channel to the bot and **reply** to it with `/id` → you get the `-100…` channel ID. (Before deploy you can also use any "user info" bot.)

## 2. MongoDB Atlas (free tier)

1. Safari → <https://www.mongodb.com/cloud/atlas/register> → sign up.
2. *Create cluster* → **Free** → any region near India (e.g. Mumbai `ap-south-1`) → Create.
3. *Database Access* → *Add new database user* → username + autogenerated password (copy it).
4. *Network Access* → *Add IP address* → **Allow access from anywhere** (`0.0.0.0/0`). Heroku dyno IPs change, so this is required; the password protects access.
5. *Clusters* → *Connect* → *Drivers* → copy the `mongodb+srv://…` string and put your password in it. That's `MONGODB_URI`.
6. Nothing else to create: the bot creates its collections and indexes on first start
   (`files`, `anime`, `episodes`, `posts`, `caption_templates`, `sources`, `settings`, `job_errors`, `users`, `fsub_requests`, `inbox`,
   and since Oct 2026 `episode_releases`, `telegram_uploads`, `pipeline_events`). New indexes are added
   automatically on start-up; existing documents are not changed.
7. Atlas Free (M0) is enough: only metadata is stored (videos live in Telegram). `pipeline_events` deletes
   itself after 60 days (TTL index).
   Existing share links in `files` keep working if you reuse the same database.

## 3. GitHub (Safari or GitHub app)

The newest code is on branch **`feature/ongoing-release-system`** (pull request into `main`). You can either:
- deploy that branch directly (Heroku step 4), or
- merge it: GitHub app → repository → *Pull requests* → open the PR → review → *Merge*.

## 4. Heroku

1. Safari → <https://dashboard.heroku.com> → **New → Create new app** → name e.g. `anime-soul-bot`, region **Europe** or **United States** → Create.
2. **Settings → Reveal Config Vars** and add (one per row, no quotes, no comments):

   | Key | Value |
   |---|---|
   | `API_ID` | from my.telegram.org |
   | `API_HASH` | from my.telegram.org |
   | `BOT_TOKEN` | from BotFather |
   | `MONGODB_URI` | from Atlas |
   | `DATABASE_NAME` | `file_share_bot` (keep the old name to keep old links) |
   | `OWNER_ID` | your numeric ID |
   | `STORAGE_CHANNEL_ID` | `-100…` storage channel |
   | `POST_CHANNEL_ID` | `-100…` ANIME SOUL channel |
   | `FSUB_CHANNELS` | e.g. `-100111…,-100222…` (optional) |
   | `DRY_RUN` | `true` for the first day |

   Optional ones are listed with defaults in `.env.example` (copy only the value, not the `# comment`).
   Useful extras: `TEST_CHANNEL_ID` (private channel for test posts), `ALLOWED_SOURCE_HOSTS`
   (host of your licensed feed), `PROCESS_MODE=auto`, `DRY_RUN_PROCESS=true` for the first test.
   Don't change existing values you already use in production unless you mean to.
3. **FFmpeg buildpack** — *Settings → Buildpacks → Add buildpack* → paste
   `https://github.com/heroku/heroku-buildpack-activestorage-preview` → Save. Then tap *⋮* next to it and
   move it **above** `heroku/python` (if your app already has a different FFmpeg buildpack, remove it).
   It installs `ffmpeg` and `ffprobe` (FFmpeg 7.1 on heroku-24). Without it `/status` shows
   `FFmpeg: MISSING` and, with `FFMPEG_REQUIRED=true`, nothing is uploaded.
4. **Deploy** tab → *Deployment method* **GitHub** → connect → search `chatgptfilesharebot` → *Connect*.
   *Manual deploy* → choose branch `main` (after merging the pull request) → **Deploy Branch**. Wait for "Your app was successfully deployed".
5. **Resources** tab → click the pencil on `worker: python main.py` → switch **on** → Confirm.
   Leave `uploader` **off** (only used in split mode, below). There is no web dyno; that's expected.
6. Logs: *More → View logs*. You should see `Started as @YourBot (role=all, dry_run=True)`.
7. Optional — *Automatic deploys* from the branch so every push redeploys.

### Process types
| Process | Command | When |
|---|---|---|
| `worker` | `python main.py` (ROLE from config, default `all`) | Always 1 dyno |
| `uploader` | `python main.py --role pipeline` | Only for split mode |

**Split mode** (keeps the bot snappy during heavy uploads): set `ROLE=bot`, then scale `uploader` to 1.
Both dynos use the same bot token; only the `bot` dyno receives updates. If both dynos accidentally
run the pipeline (e.g. `ROLE=all` **and** `uploader=1`): MongoDB job leases stop duplicate uploads/posts,
and a MongoDB **monitor lock** lets only one release monitor run (the other logs
"Another release monitor is active" and stays idle). `/status` shows who holds the lock.
Never scale `worker` above 1 — Telegram allows only one process to receive a bot's updates.

### Resource needs
- One **Basic** dyno (0.5 GB RAM) is enough for `MAX_CONCURRENT_JOBS=1` with `PROCESS_MODE=auto`:
  `auto` never re-encodes — it only remuxes (stream copy, low CPU/RAM) H.264/AAC MKVs without
  subtitles into streamable MP4, and leaves everything else as-is. Files stream to disk, not RAM.
- **Transcoding** (`PROCESS_MODE=transcode` or `MAX_OUTPUT_HEIGHT`) is CPU-heavy. On a 1x-CPU Basic dyno a
  24-minute 1080p episode can take longer than real time and may hit `FFMPEG_TIMEOUT_SECONDS`; use
  Standard-2X or a VPS for that, keep `FFMPEG_THREADS=2`, and `MAX_CONCURRENT_JOBS=1`.
- Dyno disk is **ephemeral** and wiped on every restart (at least daily). Heroku doesn't publish a fixed
  disk size, so the bot checks free space before every download/encode (`DISK_HEADROOM_MB`). The source
  file is kept until the Telegram upload is confirmed; then temp files are deleted. If a restart happens
  mid-way it re-downloads automatically. Permanent storage is the Telegram storage channel + MongoDB.

### Updating your existing app `autoanimebotu` (iPhone, about 5 minutes)
1. GitHub app → `Ic34al/chatgptfilesharebot` → **Pull requests** → *Ongoing-release system* → read
   **Files changed** → **Merge pull request** → Confirm.
2. Safari (Desktop Website) → Heroku → `autoanimebotu` → **Settings → Config Vars**. **Don't change existing values.**
   Optional new ones (all have safe defaults, so you can skip this step):
   `SCHEDULE_POST_ENABLED=false`, `SCHEDULE_POST_TIME=00:30`, `SCHEDULE_CHANNEL_ID` (empty = post channel),
   `RECONCILE_MAX_HOURS=168`, `FEED_ALERT_AFTER_FAILURES=5`. Leave `DRY_RUN=true`.
3. **Settings → Buildpacks**: check that `heroku-buildpack-activestorage-preview` is listed **above**
   `heroku/python` (gives ffmpeg + ffprobe).
4. **Deploy → Manual deploy** → branch `main` → **Deploy Branch** → wait for "successfully deployed".
5. **Resources**: `worker` on (1 dyno), `uploader` off.
6. **More → View logs**: look for `MongoDB reachable (… ms)` and `Started as @YourBot (role=all, dry_run=True)`.
   `Cannot reach MongoDB` → see Troubleshooting.
7. In Telegram send `/status`. You should see the MongoDB ping, free temp disk, pipeline counts, failure codes and
   each feed's last success. Then `/schedule` and `/queue`.

### Is the Heroku plan suitable?
| Plan | Verdict |
|---|---|
| **Eco** ($5, 1000 hours/month shared by all Eco dynos, 0.5 GB) | Works for testing. One 24/7 worker uses about 744 h, so a second Eco app or the `uploader` dyno will run out of hours. When hours run out, all Eco dynos sleep for the rest of the month. |
| **Basic** ($7/dyno, 0.5 GB, always on) | **Recommended** for `PROCESS_MODE=auto` (remux only) and `MAX_CONCURRENT_JOBS=1`. |
| **Standard-2X** ($50, 1 GB) | Only if you need transcoding (`PROCESS_MODE=transcode` / `MAX_OUTPUT_HEIGHT`). |

Limits that apply on every plan:
- The disk is temporary. It is wiped on every restart (at least once a day), and Heroku does not publish its size.
- The bot checks free space before each download.
- Jobs and history are kept in MongoDB, never on disk, so a restart only means re-downloading the file in progress.
- Telegram bot uploads are limited to 2000 MB per file.
- Feeds only list their newest entries, so long outages can still miss releases. You will get a "may be missing" alert when that happens.
- Uninterrupted uploads and complete release coverage **can't be guaranteed**. Restarts, Telegram rate limits, source outages and unannounced delays all happen.

## 5. First run (in Telegram, as the owner)
```
/adminhelp
/status
/addanime Frieren            → pick the id from the list
/addanime 154587 season=1 quality=1080p language=Japanese (English Sub)
/anime
/pending                     → upcoming episodes in IST
/captions                    → see placeholders, set per-anime templates
```
**Automatic discovery (on by default).** Every monitor cycle the bot asks AniList for the currently
airing TV/TV_SHORT/ONA anime (`AUTO_DISCOVER_MAX_PAGES` × 50, most popular first, default 200) and adds any
it doesn't know yet (marked 🛰 in `/anime`). It never re-adds a show you removed with `/removeanime`
and never overwrites settings of shows you added yourself. Season is guessed from the title
("2nd Season" → 2, otherwise 1); fix it with `/setanime <id> season=N`. Discovery only gives schedules
and episode numbers — **it does not give video files**. Delay alerts for discovered shows are grouped
into one message instead of one per episode. Turn it off with `AUTO_DISCOVER_AIRING_ANIME=false`.

Add an authorized source (one of). Until you do, aired episodes stay queued with
**`SOURCE_NOT_CONFIGURED`** (shown in `/queue`, `/status` and an owner alert) — nothing is faked:
- **Provider Telegram channel (fully automatic, recommended):** a provider who has licensed the episodes
  to you uploads them into a Telegram channel; the bot picks up each new file, matches it to the anime and
  episode, copies it to the storage channel and publishes the post with GET EPISODE — no `/attach`.
  On iPhone:
  1. Telegram → New Channel → private, e.g. "ANIME SOUL intake". Invite the provider (or their upload bot) as
     an admin who can post.
  2. Channel → Administrators → Add Admin → your bot. Bots only receive channel posts when they are admins.
  3. Find the channel ID: forward one post from the channel to your bot's owner chat with a helper such as
     @username_to_id_bot, or open the channel in web.telegram.org and use the number after `#` with `-100` in front.
  4. In your bot: `/sources add_tg partner -1001234567890 | Licence agreement #123 with Partner Ltd`
     (the bot checks that it is an admin there).
  5. Already posted files: `/sources scan partner 1` (reads from message 1 onwards).
  The provider should name files like `[Partner] Frieren S2 - 05 [1080p].mkv`, or put
  `#anilist154587` and `Episode 5` in the caption. Files that can't be matched are listed in `/unmatched`
  and you fix them with `/assign <chat:msg> <anilist id> <episode>`. Files must be videos (MKV/MP4/…), at
  most `MAX_FILE_SIZE_MB` and at least `MIN_DURATION_SECONDS`; batches are rejected.
  Use a separate intake channel — never your storage or post channel.
- **Admin upload:** reply to the episode file you are licensed to share with `/attach <id> <episode> [quality]`.
- **Partner RSS/Atom feed** (each item needs a direct-download `<enclosure>`; torrents/magnets are ignored):
  set `ALLOWED_SOURCE_HOSTS=cdn.partner.com`, then
  `/sources add_rss partner https://cdn.partner.com/anime-soul.rss | Licence agreement #123 with Partner`
- **Partner JSON feed:** set `ALLOWED_SOURCE_HOSTS=cdn.partner.com`, then
  `/sources add_feed partner https://cdn.partner.com/anime-soul.json | Licence agreement #123 with Partner`
  If the provider's API needs a key, put it in a Heroku Config Var (e.g. `PARTNER_API_KEY=Bearer abc…`) and add
  `auth_env=PARTNER_API_KEY` after the URL: `/sources add_feed partner https://… auth_env=PARTNER_API_KEY | Licence …`.
  The key is never stored in MongoDB or shown in logs. Downloads are refused if the host isn't in
  `ALLOWED_SOURCE_HOSTS` (also after redirects), resolves to a private/loopback address, is larger than
  `MAX_FILE_SIZE_MB`, or returns a non-video content type (e.g. an HTML login page); the file is then checked with FFprobe.
- **Server directory (VPS only):** set `LOCAL_SOURCE_ROOTS=/srv/library`, then
  `/sources add_dir library /srv/library/ongoing | Our own licensed library`

- **Partner HLS stream** (some licensed providers serve `.m3u8` instead of one file): in the JSON feed give the
  item `"format": "hls"` (or a URL ending in `.m3u8`). Every playlist and segment host must be in
  `ALLOWED_SOURCE_HOSTS`. Encrypted/DRM streams (`#EXT-X-KEY`) are **refused**. Ask the provider for an
  unencrypted stream or a file. FFmpeg joins the segments into one MKV, so the FFmpeg buildpack is required.

Extra tools (from AutoAnime.zip; details in docs/AUTOANIME_INTEGRATION.md). All are typed in the bot chat,
so nothing needs to change in Heroku:
- `/manage` – buttons to pause uploads, switch dry run, set auto-delete, turn mapped posts on or off.
- `/autodel 600` – files a user receives are deleted after 10 minutes (`/autodel 0` = off). Admins are exempt.
- `/ban 123456 spam` · `/unban 123456` · `/banned` · `/users`.
- `/addadmin 123456` · `/rmadmin 123456` (owner only) · `/admins`.
- `/setmap -1001234567890 154587` – also post that anime's episodes in another channel (make the bot an admin there first).
- `/restart` – restarts the bot process safely. `/ping` – quick health check (anyone).
- Users get `/search <name>` (episodes you already published) and `/ongoing` (today's schedule).
- Optional Config Var `START_PICS` = one or more `https://` image URLs, comma-separated, for a random
  picture on `/start`. Leave it unset to keep the plain welcome text.

Test the whole path safely first:
1. `DRY_RUN=true` + `DRY_RUN_PROCESS=true` → when an episode is found the bot downloads it, runs
   FFprobe/FFmpeg and sends you a report. Nothing is uploaded or posted.
2. Reply to a short video **you own** with `/testupload full` → download → FFmpeg → storage upload → test link.
3. `/testupload full publish` → TEST post in `TEST_CHANNEL_ID` (add `live` to use the main channel).
4. When the reports look right: `/dryrun off` (or set `DRY_RUN=false`).

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| App crashes: `Missing required config vars: …` | Add the listed Config Vars; the worker restarts automatically. |
| `Peer id invalid` | Bot isn't a member/admin of that channel, or the ID is wrong. Forward a post and use `/id`. |
| `CHAT_WRITE_FORBIDDEN` / `CHAT_ADMIN_REQUIRED` | Make the bot admin with *Post messages* in storage/post channels, and admin in FSUB channels. |
| Users always see "join the channel" | Bot isn't admin in the FSUB channel (membership can't be read → fails closed). `/status` + admin alerts show this. |
| "Invalid or expired file link" for old links | Old base64 tokens longer than 64 characters never reached the bot; resend the file to get a new short link. |
| No episodes appear | `/anime` empty? `/addanime`. AniList down? `/status` shows the last schedule error; the Jikan fallback creates *estimated* times. |
| `/queue` shows `SOURCE_NOT_CONFIGURED` | No authorized source is enabled. Add one with `/sources add_rss …` / `/attach`. |
| `FFMPEG_NOT_AVAILABLE` alert | Add the activestorage-preview buildpack (Heroku step 3) and redeploy. |
| `Not enough disk space` | Lower `MAX_CONCURRENT_JOBS`, or the file is too big for the dyno; it retries later. |
| `No audio stream` / `Duration too short` | The source file isn't a complete episode; it is rejected and not uploaded. |
| `ffmpeg … timed out` | Transcoding is too slow for the dyno: use `PROCESS_MODE=auto`, a bigger dyno, or raise `FFMPEG_TIMEOUT_SECONDS`. |
| Episode stuck in `airing` | No authorized file yet. You'll get a delay alert after `DELAY_ALERT_MINUTES`. `/attach` a file or check `/sources check`. |
| `failed` with "could not be confirmed" | A network error happened while posting. Check the channel. If the post is **not** there: `/retry <key> publish`. If it is there, leave it. |
| `Rejected file … SHA-256 / container / too small` | The source gave a bad or incomplete file. It is not uploaded; the bot waits for a valid one. |
| `FloodWait` in logs | Telegram rate limit; the bot waits and continues automatically. |
| MongoDB `ServerSelectionTimeoutError` | Atlas Network Access must include `0.0.0.0/0`; check the password in `MONGODB_URI` (URL-encode special characters). |
| Worker sleeps / stops | Eco dynos share 1000 h/month across the account; use Basic for 24/7. |
| `Cannot reach MongoDB (…)` in logs, worker exits | Atlas *Network Access* needs `0.0.0.0/0`; re-check `MONGODB_URI` (the URI is never printed in logs). |
| `/status` shows a feed `ERROR · backoff until …` | The feed failed several times in a row. The bot retries automatically (60 s doubling up to 1 h). Check the URL with `/sources check`. |
| Alert "Releases published in between may be missing" | The bot was offline longer than the feed's history. Check the partner's site and `/attach` any missed episode. |
| `📦 Could not deliver …` alert | The storage message was deleted or is inaccessible. Run `/checkfiles`, then `/reupload <key>`. The post and link stay the same. |
| `/queue` shows `VALIDATION_FAILED` | Size/checksum/container/duration check failed. The file was not uploaded; the bot waits for a valid file. |
| Build fails on Python version | Keep `.python-version` = `3.11`; delete any `runtime.txt`. |

## Paid services and platform limits

| Item | Cost / limit |
|---|---|
| Heroku Basic dyno (recommended) | $7/month per dyno; split mode = 2 dynos |
| Heroku Eco | $5/month for 1000 shared hours (one 24/7 dyno ≈ 744 h) |
| MongoDB Atlas Free | $0 — 512 MB storage, 100 ops/s, 10 GB in/out per 7 days (only metadata is stored, plenty) |
| AniList API | Free — 90 req/min (30 when degraded); the bot uses ≈ 2–4 per cycle |
| Jikan API | Free, rate-limited; fallback only |
| Telegram | Free. Bot uploads ≤ 2000 MB per file (MTProto), captions ≤ 1024 chars, `/start` payload ≤ 64 chars, broadcasts ≈ 20–30 msg/s |
| Content licences | Required from rights holders for any episode you redistribute — not provided by this software |
